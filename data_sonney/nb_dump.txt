# Testing the e-BAHAGI beneficiary-qualification algorithm

This notebook tests the **real, unmodified** qualification algorithm from
[`checker/logic.py`](../checker/logic.py) — it is imported directly from the
Django app, not reimplemented here — against the real citizen registry
export in [`citizen_registry_data.xlsx`](./citizen_registry_data.xlsx)
(~43,400 residents across 47 barangays).

The algorithm is a decision tree:

```
Is member of a valid class?
  No  -> Not qualified
  Yes -> Received a grant within the last 3 months (self or household)?
           Yes -> Not qualified
           No  -> Monthly income < Php 15,000.00?
                    Yes -> QUALIFIED
                    No  -> Not qualified
```

**Data caveat found during profiling (see Part 2):** the registry file has
**no `monthly_income` values at all (100% empty)** and **no grant-history /
household columns**. Those two inputs are required by the algorithm but
don't exist in this export, so Parts 4+ clearly label them as *simulated*
placeholders used only to exercise the algorithm at realistic scale — they
are not real eligibility results. Part 1 covers the algorithm itself with
exact, hand-picked test cases that don't depend on simulated data.

**Structure**
1. Unit tests for `evaluate()` — every branch, boundary values
2. Load & profile the real registry data
3. Derive `beneficiary_class` from registry columns (PWD/solo-parent flags, age, occupation)
4. Simulate the two missing inputs (income, recent-grant flag) — clearly labeled
5. Run the real algorithm across all ~43k residents
6. Breakdowns (by class, by barangay, by rejection reason)
7. Sensitivity sweep on the income threshold (exercises the real constant, not a copy)
8. Export results
9. Flowchart of the rule-based decision tree (drawn programmatically from the real constants)
10. ML-style testing of the algorithm — confusion matrix, precision/recall/F1/ROC-AUC, and a learned decision-tree plot

cases = [
    ("invalid class is always rejected",
     dict(beneficiary_class="Barangay Captain", received_grant_within_3_months=False, monthly_income=1000),
     False),
    ("None is rejected as an invalid class",
     dict(beneficiary_class=None, received_grant_within_3_months=False, monthly_income=1000),
     False),
    ("valid class + recent grant -> rejected regardless of income",

     False),
    ("income exactly AT the threshold is NOT qualified (strict <)",
     dict(beneficiary_class="Rice Farmer", received_grant_within_3_months=False, monthly_income=15000.00),
     False),
    ("income one centavo below the threshold IS qualified",
     dict(beneficiary_class="Rice Farmer", received_grant_within_3_months=False, monthly_income=14999.99),
     True),
    ("zero income qualifies",
     dict(beneficiary_class="Senior Citizen", received_grant_within_3_months=False, monthly_income=0),
     True),
    ("high income is rejected",
     dict(beneficiary_class="Senior Citizen", received_grant_within_3_months=False, monthly_income=50000),
     False),
]

failures = 0
for description, kwargs, expected in cases:
    outcome = evaluate(**kwargs)
    ok = outcome["qualified"] == expected
    failures += not ok
    print(f"[{'PASS' if ok else 'FAIL'}] {description}")
    print(f"       -> qualified={outcome['qualified']}  reason={outcome['reason']!r}")
    assert ok, f"{description}: expected qualified={expected}, got {outcome}"

# Every documented valid class must be individually recognized.
for cls in VALID_CLASSES:
    outcome = evaluate(beneficiary_class=cls, received_grant_within_3_months=False, monthly_income=0)
    ok = outcome["qualified"] is True
    failures += not ok
    print(f"[{'PASS' if ok else 'FAIL'}] class recognized: {cls}")
    assert ok, f"VALID_CLASSES entry {cls!r} did not qualify under ideal conditions: {outcome}"

print(f"\n{len(cases) + len(VALID_CLASSES)} checks run, {failures} failed.")

## Part 3 — Derive `beneficiary_class` from the registry columns

`evaluate()` takes a single `beneficiary_class` string, but a resident can
match more than one real-world category (e.g. a senior citizen who is also
PWD). For this notebook we pick **one** class per person using a fixed
priority order so every row can be run through the algorithm, and we also
keep the full match list so we can measure how often that overlap happens.

Priority: `PWD` > `Solo Parent` > `Senior Citizen` (age ≥ 60) > occupation
keyword match on `psoc` (Tricycle Driver / Construction Worker / Rice Farmer
/ Market Vendor — the same keyword-matching approach already used in
`beneficiaries/management/commands/import_beneficiaries.py`).

**Known gap:** `Lactating Mother` can never be derived from this file — there
is no pregnancy/maternity column — so it will never appear below. That's a
data-source limitation, not a bug in the algorithm.


=== Cell 10 code ===
PSOC_CLASS_PATTERNS = [
    ("Tricycle Driver", re.compile(r"TRICYCLE|PEDICAB", re.I)),
    ("Construction Worker", re.compile(r"CONSTRUCTION", re.I)),
    ("Rice Farmer", re.compile(r"RICE FARMER", re.I)),
    ("Market Vendor", re.compile(r"VENDOR", re.I)),
]

def matched_classes_for_row(row):
    matches = []
    if row["pwd"] == "Yes":
        matches.append("PWD")
    if row["solo parent"] == "Yes":
        matches.append("Solo Parent")
    if row["age"] >= 60:
        matches.append("Senior Citizen")
    psoc = row["psoc"]
    psoc = psoc if isinstance(psoc, str) else ""
    for cls, pattern in PSOC_CLASS_PATTERNS:
        if pattern.search(psoc):
            matches.append(cls)
            break
    return matches

df["matched_classes"] = df.apply(matched_classes_for_row, axis=1)
df["num_matched_classes"] = df["matched_classes"].str.len()
df["beneficiary_class"] = df["matched_classes"].apply(lambda m: m[0] if m else None)

assert set(df["beneficiary_class"].dropna().unique()) <= set(VALID_CLASSES), \
    "derived a class that evaluate() would not recognize"

print("'Lactating Mother' present in derived classes:",
      "Lactating Mother" in df["beneficiary_class"].values, "(expected: False)")
print()
print("Residents matching 2+ classes at once:", (df['num_matched_classes'] >= 2).sum())
df["beneficiary_class"].value_counts(dropna=False)

def run_evaluate(row):
    outcome = evaluate(
        beneficiary_class=row["beneficiary_class"],
        received_grant_within_3_months=bool(row["sim_received_grant_recently"]),
        monthly_income=float(row["sim_monthly_income"]),
    )
    return pd.Series({
        "decision": outcome["result"],
        "reason": outcome["reason"],
        "qualified": outcome["qualified"],
    })

df = pd.concat([df, df.apply(run_evaluate, axis=1)], axis=1)

def categorize_reason(reason):
    if reason.startswith("Not a member"):
        return "not in a valid class"
    if reason.startswith("Received a grant"):
        return "recent grant (self)"
    if "family member" in reason:
        return "recent grant (household)"
    if reason.startswith("Monthly income"):
        return "income too high"
    return "qualified"

## Part 7 — Sensitivity to the income threshold

`INCOME_THRESHOLD` is a module-level constant in `checker/logic.py`. Rather
than copying the comparison, this temporarily overrides the real constant on
the imported module and re-runs the real `evaluate()` for each candidate
threshold, then restores the original value.


=== Cell 22 code ===
thresholds_to_try = [8000, 10000, 12000, 15000, 18000, 20000]
original_threshold = checker_logic.INCOME_THRESHOLD
sweep_rows = []

try:
    for t in thresholds_to_try:
        checker_logic.INCOME_THRESHOLD = t
        qualified_count = int(df.apply(
            lambda row: evaluate(
                beneficiary_class=row["beneficiary_class"],
                received_grant_within_3_months=bool(row["sim_received_grant_recently"]),
                monthly_income=float(row["sim_monthly_income"]),
            )["qualified"],
            axis=1,
        ).sum())
        sweep_rows.append((t, qualified_count))
finally:
    checker_logic.INCOME_THRESHOLD = original_threshold

assert checker_logic.INCOME_THRESHOLD == original_threshold, "threshold was not restored"

sweep_df = pd.DataFrame(sweep_rows, columns=["income_threshold", "qualified_count"])
ax = sweep_df.plot.bar(x="income_threshold", y="qualified_count", legend=False, color="#4C72B0")
ax.axvline(sweep_df.index[sweep_df["income_threshold"] == 15000][0], color="#C44E52", linestyle="--", linewidth=1)

import matplotlib.patches as mpatches

def draw_box(ax, x, y, w, h, text, facecolor="white", fontsize=6.8):
    box = mpatches.FancyBboxPatch(
        (x - w / 2, y - h / 2), w, h,
        boxstyle="round,pad=0.02,rounding_size=0.04",
        linewidth=1, edgecolor="black", facecolor=facecolor, zorder=2,
    )
    ax.add_patch(box)
    ax.text(x, y, text, ha="center", va="center", fontsize=fontsize, zorder=3)

def draw_arrow(ax, xy0, xy1, label=None):
    ax.annotate("", xy=xy1, xytext=xy0,
                arrowprops=dict(arrowstyle="-", linewidth=0.8, color="#555555"), zorder=1)
    if label:
        mx, my = (xy0[0] + xy1[0]) / 2, (xy0[1] + xy1[1]) / 2
        ax.text(mx, my, label, fontsize=6.2, ha="center", va="center",
                color="#333333", backgroundcolor="white", zorder=3)

n = len(VALID_CLASSES)
col_w = 3.0
xs = [i * col_w for i in range(n)]
root_x = sum(xs) / n

class_h, class_w = 0.5, 2.4
q_h, q_w = 0.7, 2.2
leaf_h, leaf_w = 0.45, 1.1
y_root, y_class, y_grant, y_grant_leaf, y_income, y_income_leaf = 10.2, 9.0, 7.4, 6.0, 4.6, 3.2

fig, ax = plt.subplots(figsize=(2.7 * n, 7.5))
draw_box(ax, root_x, y_root, 2.8, 0.55, "Citizen / applicant", facecolor="#DCE6F7", fontsize=8)

grant_label = "Received grant" + chr(10) + "within 3 months?"

for x, cls in zip(xs, VALID_CLASSES):
    draw_box(ax, x, y_class, class_w, class_h, cls, facecolor="#EFEFEF")
    draw_arrow(ax, (root_x, y_root - 0.28), (x, y_class + class_h / 2))

    draw_box(ax, x, y_grant, q_w, q_h, grant_label)
    draw_arrow(ax, (x, y_class - class_h / 2), (x, y_grant + q_h / 2))

    nq1_x = x - 0.75
    draw_box(ax, nq1_x, y_grant_leaf, leaf_w, leaf_h, "Not qualified", facecolor="#F7D9D9", fontsize=6.5)
    draw_arrow(ax, (x - 0.35, y_grant - q_h / 2), (nq1_x, y_grant_leaf + leaf_h / 2), label="Yes")

    income_label = f"Income <{chr(10)}Php {INCOME_THRESHOLD:,.0f}?"
    income_x = x + 0.75
    draw_box(ax, income_x, y_income, q_w, q_h, income_label)
    draw_arrow(ax, (x + 0.35, y_grant - q_h / 2), (income_x, y_income + q_h / 2), label="No")

    q_x = income_x - 0.75
    nq2_x = income_x + 0.75
    draw_box(ax, q_x, y_income_leaf, leaf_w, leaf_h, "Qualified", facecolor="#DBF0DB", fontsize=6.5)
    draw_box(ax, nq2_x, y_income_leaf, leaf_w, leaf_h, "Not qualified", facecolor="#F7D9D9", fontsize=6.5)
    draw_arrow(ax, (income_x - 0.35, y_income - q_h / 2), (q_x, y_income_leaf + leaf_h / 2), label="Yes")
    draw_arrow(ax, (income_x + 0.35, y_income - q_h / 2), (nq2_x, y_income_leaf + leaf_h / 2), label="No")

ax.set_xlim(xs[0] - 2.0, xs[-1] + 2.6)
ax.set_ylim(y_income_leaf - 0.6, y_root + 0.6)
ax.axis("off")
ax.set_title("evaluate() decision tree - generated from VALID_CLASSES / INCOME_THRESHOLD", fontsize=11)

## Part 10 — ML-style testing of the algorithm

`evaluate()` is an exact, deterministic rule — Part 1 already tests it
completely on its own terms. This section additionally runs the
confusion-matrix / precision-recall-F1 / ROC-AUC / decision-tree-plot battery
you'd use to test a *learned* classifier, applied to this project's own data,
for anyone whose testing checklist expects that format.

**Sanity check first.** If a `DecisionTreeClassifier` is given the exact same
three inputs `evaluate()` uses (class, grant flag, true income), it should
reconstruct the rule perfectly — `qualified` is a noise-free deterministic
function of exactly those features, so 100% is the *correct* result here,
not a bug.

=== Cell 29 markdown ===
### A more realistic test: self-reported income has measurement error

`evaluate()` needs *true* monthly income, but a real intake interview or
household survey collects *reported* income — people round, forget irregular
earnings, or under/over-report. To get metrics that mean something (rather
than the trivial 100% above), this fits the model on a **noisy** income
feature — true income distorted by +/-25% random error — while the label
still comes from the true, unmodified `evaluate()` decision. This is the
same battery shown in the reference screenshots, run against this project's
own algorithm and data; exact numbers will vary with the random seed and are
not meant to match any other run.
